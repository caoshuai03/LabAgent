# 思考过程流式展示设计

> 2026-07-26 已完成第一版落地：主 Agent 推理流、历史持久化与前端折叠展示均已接入。本文同时保留展示边界与后续约束。

## 1. 目标与结论

当前 `qwen3.5:35b`、`deepseek-r1` 等推理模型可能产生 thinking 内容，但前端只渲染最终 `token`，没有单独展示思考过程。

设计结论：

1. 新增结构化 SSE 事件 `reasoning_token`，只承载可展示的主 Agent 思考片段。
2. 前端参考 Codex：在助手消息正文上方展示“正在思考/已思考完成”的折叠面板；流式生成时默认展开，思考结束后自动折叠，用户可手动展开查看。
3. 不是所有模型调用都展示思考。只展示最终回答链路里的 `agent` 节点思考；`rerank`、MultiQuery 查询改写、会话标题生成、embedding、工具内部总结等内部调用全部不展示。
4. 后端继续把最终回答走 `token` 事件，思考内容不能混入 `content`，避免污染 Markdown、复制、历史答案和 RAG 评测。
5. 历史恢复通过 `chat_message.reasoning` JSONB 字段存储多段结构化思考，而不是塞进正文隐藏注释。

## 2. 展示边界

### 2.1 允许展示

| 调用位置 | 是否展示 | 原因 |
| --- | --- | --- |
| `agent` 节点首次回答 | 是 | 用户直接等待的主要推理过程 |
| `agent` 工具调用后继续回答 | 是 | 属于同一次用户请求的可理解推理 |
| `/react-agent/resume` 审批恢复后的 `agent` | 是 | 用户批准/拒绝后继续生成，仍面向当前助手消息 |

### 2.2 不展示

| 调用位置 | 是否展示 | 原因 |
| --- | --- | --- |
| `rerank` | 否 | 内部排序，不应暴露候选文档判断细节 |
| MultiQuery 查询改写 | 否 | 内部检索扩展，展示会干扰用户 |
| 会话标题生成 | 否 | 异步后台任务，不属于回答过程 |
| embedding | 否 | 无自然语言思考内容 |
| 工具内部二次总结 | 否 | 工具结果已有 `tool_result/status` 展示 |

当前代码中 `get_query_rewrite_model()`、`get_rerank_model()`、`get_conversation_title_model()` 对本地模型已设置 `reasoning=False`，后续仍保持这个边界。

## 3. SSE 协议

新增事件：

```json
{
  "event_type": "reasoning_token",
  "session_id": "uuid",
  "trace_id": "trace",
  "payload": {
    "content": "正在分析用户问题...",
    "reasoning_id": "agent-1",
    "phase": "agent",
    "round_number": 1
  }
}
```

可选完成事件：

```json
{
  "event_type": "reasoning_done",
  "session_id": "uuid",
  "trace_id": "trace",
  "payload": {
    "reasoning_id": "agent-1",
    "phase": "agent",
    "round_number": 1
  }
}
```

字段约定：

| 字段 | 说明 |
| --- | --- |
| `content` | 本次增量思考文本 |
| `reasoning_id` | 一段思考的稳定 ID，同一轮连续追加 |
| `phase` | 当前固定为 `agent`，预留未来扩展 |
| `round_number` | Agent 轮次，用于多次模型调用分段展示 |

`final` 事件仍表示整轮回答结束。即使没有 `reasoning_done`，前端也应在收到 `final`、`error`、`paused` 或连接结束时把当前思考段标记完成。

## 4. 后端设计

### 4.1 提取方式

在 `AiService._stream_graph()` 的 `messages` 分支中，仅处理 `meta.langgraph_node == "agent"` 的 `AIMessageChunk`。

提取优先级：

1. 优先读取模型适配器暴露的结构化 reasoning 字段，例如 `additional_kwargs.reasoning_content` 或同类字段。
2. 兼容 `<think>...</think>` 标签流：标签内内容转为 `reasoning_token`，标签外内容继续转为 `token`。
3. 对没有 reasoning 的模型，不发送 `reasoning_token`，前端保持现状。

### 4.2 过滤原则

后端必须用 `meta.langgraph_node` 做第一层过滤：

```text
非 agent 节点 -> 不提取 reasoning，不下发 reasoning_token
agent 节点 -> 可提取 reasoning，并保持 answer token 独立
```

这能保证 `rerank`、检索、标题等内部调用不会被前端看到。

### 4.3 持久化

已新增字段：

```text
chat_message.reasoning JSONB nullable
```

推荐结构：

```json
[
  {
    "reasoning_id": "agent-1",
    "phase": "agent",
    "round_number": 1,
    "content": "完整思考文本"
  }
]
```

`ChatMessageVO` 增加 `reasoning: list[ChatReasoningVO]`，字段保持蛇形。历史接口返回后，前端直接恢复折叠态展示。

## 5. 前端设计

### 5.1 数据结构

助手消息增加：

```js
{
  reasoning: [
    {
      reasoning_id: 'agent-1',
      phase: 'agent',
      round_number: 1,
      content: '',
      is_complete: false,
      collapsed: false
    }
  ]
}
```

`ChatInput.vue` 增加事件处理：

- `reasoning_token`：按 `reasoning_id` 找到或创建思考段，追加 `payload.content`。
- `reasoning_done`：标记该段完成并自动折叠。
- `final/error/paused/onComplete`：兜底把未完成思考段标记完成并折叠。

### 5.2 UI 位置

在 `MessageItem.vue` 中，展示顺序建议为：

```text
思考过程面板
工具活动面板
助手正文
工具审批
引用来源
消息操作
```

理由：思考发生在回答前，工具活动是执行过程，正文是最终答案。

### 5.3 交互

1. 流式思考中：标题显示“正在思考”，面板默认展开。
2. 思考结束：标题显示“已思考完成”，自动折叠。
3. 用户点击标题：手动展开/折叠，后续自动折叠不覆盖用户选择。
4. 多次 Agent 调用：每一轮形成一段，默认只展开当前正在生成的一段。
5. 没有思考内容：不渲染面板。

视觉上复用现有 Codex 风格工具活动面板的克制样式：小标题、左侧细边、浅背景、等宽或普通文本均可，不做大卡片。

## 6. 安全与隐私

1. `reasoning_token` 不展示内部节点，避免泄露 rerank 候选、工具策略和系统提示。
2. 当前实现限制单段最多 4000 字、整条消息最多 12000 字，超长内容截断。
3. 思考内容以 Vue 文本插值渲染，不进入 Markdown 或 `v-html`，避免模型输出注入页面结构。
4. 默认只对普通用户可见自己的会话思考，历史查询仍走现有 JWT 会话归属校验。

## 7. 已完成范围

1. 后端新增 reasoning 解析器，覆盖结构化字段和 `<think>` 标签两种来源。
2. `AiService._stream_graph()` 新增 `reasoning_token/reasoning_done` 下发，只允许 `agent` 节点。
3. `chat_message` 新增 `reasoning` 字段，schema、repository、history 返回同步补齐。
4. 前端 store 增加 `appendReasoningToLastMessage()`、`completeLastMessageReasoning()`。
5. `ChatInput.vue` 处理新增 SSE 事件。
6. `MessageItem.vue` 新增 `ReasoningPanel` 或本地子块，完成自动折叠。
7. 补测试：SSE 解析、非 agent 节点过滤、历史恢复、思考结束自动折叠。

## 8. 验收标准

1. 使用带 thinking 的聊天模型时，前端能实时看到思考过程。
2. 最终答案开始输出或整轮 `final` 后，思考面板自动折叠。
3. 工具调用后多次进入 Agent 时，思考按轮次分段展示。
4. `rerank`、查询改写、标题生成不会产生前端思考面板。
5. 刷新历史会话后，已保存的思考过程仍可折叠查看。
6. 复制助手正文时不包含思考过程。
