# 第二阶段：基础后端设计

> 本文档是 LabAgent 第二阶段产出，基于第一阶段 [产品与架构设计](./01-产品与架构设计.md)，
> 面向「基础后端」落地：搭建 FastAPI 工程骨架，完成用户认证、管理员权限、PostgreSQL 数据访问、
> 会话与消息、MinIO 文件存储、Ollama/外部模型统一适配，以及 Docker Compose 编排。
> 目标是把参考项目 JavaLabAgent 的基础能力平移到 Python 技术栈，安全项从第一天纳入。
> 本文档为设计方案，尚未落地；RAG 闭环与 Agent 编排分别在第三、第四阶段实现。

---

## 一、本阶段目标与范围

### 1.1 本阶段实现

- FastAPI 工程骨架（配置、依赖注入、异常处理、统一响应、路由分层）。
- 用户认证：注册、登录、登出、修改密码、JWT 签发与校验。
- 管理员权限校验。
- PostgreSQL 数据访问（SQLAlchemy 2.0 异步 + Alembic 迁移）。
- 会话与消息的持久化与查询（含滑动窗口读取，为第三阶段 RAG 预留）。
- MinIO 文件存储封装（上传 / 删除 / 下载流 / 预签名 URL）。
- 模型统一适配层（Ollama 本地 + OpenAI 兼容外部模型路由），本阶段仅打通调用与路由，暂不接 RAG 检索。
- 用户反馈提交接口。
- Docker Compose 一键编排（FastAPI + PostgreSQL/pgvector + MinIO）。
- 要验证跑通

### 1.2 本阶段不实现（后续阶段）

- 文档解析 / 切分 / 向量化 / 检索（第三阶段）。
- LangGraph Agent 状态图与受控工具（第四阶段）。
- Skills 加载与注入（随第四阶段或按需）。
- MCP、OSS、多模态等（详见第一阶段功能边界）。

> 说明：只留下一个对话接口，`/api/v1/ai/agent` 
> 知识检索与 Agent 编排留待后续阶段增强，接口契约保持不变。

## 二·补充、框架能力优先原则（重要）

> 这是本次迁移的一条核心方针，也是参考项目 JavaLabAgent 做得不好的地方：**它把很多本应由框架提供的能力都自己手写了**
> （例如手写滑动窗口记忆、手写滚动摘要、手写会话状态拼接、手写工具调用循环）。V2 迁移到 LangGraph 后，
> **凡是框架已提供的能力，一律优先使用框架能力，不再自研**；只有框架未覆盖或需要贴合教学业务的部分才自己写。

### 应当改用框架能力（而非自研）的清单

| 能力 | 参考项目做法（自研） | V2 用框架能力替代 | 说明 |
| :--- | :--- | :--- | :--- |
| 短期记忆 / 会话上下文 | 手写滑动窗口：查最近 N 条、倒序再反转、手工拼进 prompt | LangGraph **checkpointer**（`AsyncPostgresSaver`）+ `MessagesState`，按 `thread_id`（=会话ID）自动持久化与恢复对话状态 | 复用现有 PostgreSQL，框架自动管理 checkpoint 表 |
| 会话历史管理 | 手写消息拼接与传递 | LangGraph `MessagesState` + `add_messages` reducer 自动累加消息 | 无需手工维护消息数组 |
| 滚动摘要 / 上下文裁剪 | 手写 `SummaryService` 计数触发摘要 | LangGraph 内置消息管理：`trim_messages` 裁剪、`RemoveMessage` 删除、官方 summarize 模式 | 优先用内置裁剪；确需摘要时按官方 summarize 节点模式做 |
| 流式输出 | 手工组装 SSE 分片 | LangGraph 图 `.astream(..., stream_mode="messages")` 原生 token 流，FastAPI 仅做 SSE 透传 | 减少手写流式拼接 |
| Agent / 工具调用循环 | （React Agent）手写 think-act 循环 | LangGraph 预构建 `create_react_agent` 或自定义 `StateGraph` + `ToolNode` | 第四阶段落地，本阶段先不实现 |
| 工具定义与参数校验 | 手写 JSON schema 与参数解析 | LangGraph 生态 `@tool` + Pydantic 自动生成 schema 与校验 | 第四阶段 |
| 模型抽象 / 多provider | 手写 provider 分发 | 集成包 `langchain-ollama` / `langchain-openai` 提供的 `ChatOllama` / `ChatOpenAI`，统一 `Runnable` 接口 | 见第八章 |
| 提示词编排 | 字符串手工拼接 | LangGraph 生态 `ChatPromptTemplate` / `MessagesPlaceholder` | 结构化拼接 |
| 人工干预 / 断点续跑 | 无 | LangGraph **human-in-the-loop**（interrupt）与 durable execution | 教学审核场景的未来可选项 |

### 仍需自己实现（框架不覆盖或属于业务层）的部分

- 用户认证 / JWT / 管理员权限（属 Web 层，见第四章）。
- 业务数据表与 Repository（`tb_user`、`kb_file`、`tb_user_feedback` 等业务实体）。
- MinIO 文件存储封装（对象存储属基础设施）。
- 教学业务的受控工具**内部逻辑**（如查实验要求），但工具的**定义/调度**用框架。
- 会话的业务级增删查（列表展示、逻辑删除、归属校验）——注意与 checkpointer 的「对话状态」分工：业务表存会话元数据与展示用消息，checkpointer 存供模型使用的图状态。

### 落地约束

- 引入 `langgraph` 依赖；checkpointer 使用 `langgraph-checkpoint-postgres` 的 `AsyncPostgresSaver`，复用现有 PostgreSQL。
- 不确定框架是否提供某能力时，先查 LangGraph 官方文档确认，**禁止臆测 API 名称与用法**再决定是否自研。

## 四、认证与权限设计

### 4.1 请求上下文

参考项目用 `ThreadLocal`（[BaseContext.java](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/common/BaseContext.java)）保存当前用户 ID。FastAPI 为异步模型，**必须用 `contextvars.ContextVar` 而非线程局部变量**，或更推荐直接用 FastAPI 依赖注入把 `current_user` 传入路由，避免全局状态。本项目推荐依赖注入为主。

### 4.2 JWT

- 使用 PyJWT，HS256，密钥从环境变量 `JWT_SECRET_KEY` 读取（禁止硬编码，参考项目 `cssecret` 明文必须替换）。
- 载荷含 `user_id` 与 `exp`；TTL 通过配置项 `JWT_TTL_SECONDS`。
- 请求头沿用 `Authorization: Bearer <token>`，与参考项目 [JwtTokenUserInterceptor](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/common/JwtTokenUserInterceptor.java) 的解析方式一致，便于前端复用。

### 4.3 认证依赖

用 FastAPI `Depends` 实现两级依赖，替代参考项目的两个拦截器：

- `get_current_user`：解析并校验 JWT，查库确认用户存在且启用（`status=1`），返回用户对象；失败抛 401。
- `require_admin`：在 `get_current_user` 基础上校验 `role == 1`，否则 403。对应参考项目 [AdminInterceptor](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/common/AdminInterceptor.java)。

登录、注册接口不加认证依赖，其余 `/api/v1/**` 均需 `get_current_user`；知识库上传/删除、用户管理类接口叠加 `require_admin`。

### 4.4 密码安全

- 存储：Argon2（首选）或 bcrypt，**替换参考项目的 MD5**。
- 登录、改密时用哈希校验；改密时旧密码校验同样走哈希。
- 初始管理员账号在 Alembic 迁移或启动脚本中用 Argon2 重新生成哈希写入。

### 4.5 安全基线（本阶段必须满足）

- 当前用户 ID 一律取自 JWT，**禁止信任请求体的 `userId`**（参考项目 DTO 里带 `userId`，V2 需忽略并以 token 为准）。
- 会话 / 消息查询与删除必须校验资源归属（`user_id` 匹配）。
- 上传文件校验：大小上限、扩展名白名单（pdf/md/txt 等）、MIME 类型、文件名净化（防路径穿越）。
- 日志禁止输出密码、JWT、API Key。
- 外部调用（Ollama / OpenAI / MinIO）设置连接与读取超时。

## 五、数据访问设计

### 5.1 ORM 模型（对齐第一阶段迁移方案）

以 [init.sql](file:///Users/bytedance/learnAgent/JavaLabAgent/sql/init.sql) 为基线映射为 SQLAlchemy 模型：

| 模型 | 表 | 关键调整 |
| :--- | :--- | :--- |

| `ChatSession` | `chat_session` | 保留 `summary`、逻辑删除 `deleted` |

- Alembic 管理迁移，以 init.sql 结构为初始版本基线。

## 六、会话与消息设计

对齐参考项目 [ChatSessionService](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/service/ChatSessionService.java) 与 [ChatMessageService](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/service/ChatMessageService.java)，但**遵循第二·补充章的「框架能力优先」原则**，区分两类职责：

**A. 业务层（自己实现）——会话元数据与展示**

- `SessionService`：`get_or_create_session`、`list_sessions_by_user`（按 `updated_at` 倒序、过滤 `deleted=0`）、`update_session_time`、`delete_session` / `delete_sessions`（逻辑删除 + 归属校验）。
- `MessageService`：持久化用户/助手消息到 `chat_message`，供前端历史展示（`get_messages_by_session`，含归属校验）。会话标题取首条用户消息截断。
- 会话业务 ID 作为 LangGraph 的 `thread_id`，打通业务会话与图状态。

**B. 对话上下文 / 记忆（改用框架能力，不再自研滑动窗口）**

- **不再手写**参考项目的「查最近 N 条 → 倒序 → 反转 → 手工拼 prompt」滑动窗口逻辑。
- 改用 LangGraph **checkpointer**（`AsyncPostgresSaver`，复用现有 PostgreSQL）+ `MessagesState`：以 `thread_id` 自动持久化与恢复对话状态，喂给模型的历史由框架管理。
- 上下文过长时用框架内置的 `trim_messages` 裁剪；确需摘要时按官方 summarize 节点模式实现，**不再手写 `SummaryService` 计数触发逻辑**。
- 移除自研常量 `MEMORY_SIZE=10` 的手工窗口实现；如需限制窗口，通过 `trim_messages` 的参数配置。

> 分工要点：`chat_message` 表用于**前端历史展示与审计**；checkpointer 存储的是**供模型推理的图状态**。两者各司其职，避免像参考项目那样用一套手写逻辑既做展示又做上下文。

本阶段对话接口先实现：持久化用户消息（业务表）→ 通过 LangGraph 图 `.astream` 调模型流式生成（上下文由 checkpointer 提供）→ 持久化助手消息（业务表）。

## 七、MinIO 存储设计

对齐参考项目 [StorageUtil](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/utils/StorageUtil.java) / [MinioUtil](file:///Users/bytedance/learnAgent/JavaLabAgent/javalab-agent-back/src/main/java/com/cs/rag/utils/MinioUtil.java)，抽象 `StorageService`：

- 方法：`upload(data, object_name) -> url`、`delete(object_name)`、`get_object(object_name) -> stream`、`get_presigned_url(object_name, expire_minutes)`。
- 启动时确保 bucket 存在。
- 对象前缀统一（如 `lab-agent-rag/`），替代参考项目的 `java-lab-agent-rag/`。
- **修正参考项目问题**：`download()` 里写死了 Windows 路径 `D:\fileOSS`，V2 不实现「下载到服务器本地」这种无意义方法，仅保留流式下载 `get_object` 与预签名 URL。
- MinIO SDK 为同步库，在异步接口中需用 `run_in_executor` / `anyio.to_thread` 隔离，避免阻塞事件循环。
- 配置从环境变量读取：`MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`。

## 九、API 契约（本阶段实现的接口）

沿用第一阶段 [API 兼容清单](./01-产品与架构设计.md#五api-兼容清单)，本阶段落地以下模块（统一前缀 `/api/v1`，统一 `BaseResponse` 结构）：

- `/user`：register、login、logout、updatePassword、addUser(admin)、page(admin)、status/{status}(admin)、{id}、update、update/info、validate。
- `/ai`：rag、react-agent（SSE，本阶段模型直连）、rag/history、rag/sessions、rag/sessions/delete。
- `/knowledge`：本阶段可先实现文件记录 CRUD 与 MinIO 存取骨架，解析/向量化留第三阶段。
- `/feedback`：submit。
- `/skills`：可先返回空/骨架，随后续阶段完善。

请求体中的 `userId` 一律忽略，以 JWT 用户为准。SSE 使用 FastAPI `StreamingResponse`，`media_type=text/event-stream`。

## 十、Docker 编排设计

对齐参考项目 [docker-compose.yml](file:///Users/bytedance/learnAgent/JavaLabAgent/docker-compose.yml)，服务组成：

| 服务 | 镜像 | 说明 |
| :--- | :--- | :--- |
| `postgres` | `ankane/pgvector` | 首次启动执行 `sql/init.sql`；健康检查 `pg_isready` |
| `minio` | `minio/minio` | 9000 API / 9001 控制台；数据卷持久化 |
| `backend` | 自建（Python + Uvicorn） | 依赖 postgres 健康、minio 启动；env 注入配置 |
| `frontend` | 自建（后续阶段） | nginx 静态站点 |

后端 Dockerfile：基于 `python:3.12-slim`，装依赖后用 `uvicorn app.main:app` 启动；容器启动前执行 `alembic upgrade head`。

环境变量（`.env.example` 需新增/调整）：`JWT_SECRET_KEY`、`JWT_TTL_SECONDS`、`OLLAMA_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`POSTGRES_*`、`MINIO_*`。移除 MCP 相关的 `AMAP_MAPS_API_KEY` / `TAVILY_API_KEY`（本阶段不迁移 MCP）。

## 十一、验收标准

- FastAPI 启动，Swagger（`/docs`）可访问，`/api/v1` 路由注册完整。
- 注册 → 登录拿到 JWT → 携带 JWT 访问受保护接口成功；无/错 token 返回 401。
- 非管理员访问 admin 接口返回 403；管理员通过。
- 密码以 Argon2/bcrypt 存储，登录校验通过；MD5 已彻底移除。
- 会话可创建 / 列表 / 删除（逻辑删除 + 归属校验）；消息可持久化并按滑动窗口读取。
- 对话接口能 SSE 流式返回模型输出，用户与助手消息均落库。
- 文件可上传到 MinIO 并生成可访问 URL；可流式下载。
- `docker compose up` 一键拉起 postgres + minio + backend，迁移自动执行。
- 安全基线：请求体 `userId` 被忽略、上传文件校验生效、密钥全部来自环境变量。

## 十二、本阶段结论

- 本阶段把 JavaLabAgent 的认证、权限、数据访问、会话消息、存储、模型适配平移到 FastAPI 技术栈，并修正参考项目的安全与实现问题（MD5→Argon2、ThreadLocal→依赖注入/ContextVar、去除写死本地下载路径、密钥环境化）。
