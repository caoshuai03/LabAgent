# LabAgent 离线部署

## 1. 环境说明

| 项目 | 配置 |
|---|---|
| 本地构建环境 | macOS，项目目录 `/Users/bytedance/learnAgent/LabAgent` |
| 服务器 | `cs@172.29.7.233` |
| 服务器架构 | `linux/amd64`（`x86_64`） |
| 服务器部署目录 | `/home/cs/labagent/labagent-offline` |
| 部署方式 | 本地构建 Docker 镜像，上传后由 Docker Compose 重启 |
| Ollama | 直接运行在服务器宿主机 |
| 应用配置 | 统一使用项目根目录 `.env` |

服务器不能访问互联网，因此所有业务镜像必须在本地构建为 `linux/amd64` 后上传。应用源码已经包含在镜像中，不需要单独上传。

## 2. 部署结构

服务器目录保持为：

```text
/home/cs/labagent/
├── labagent-update.tar
└── labagent-offline/
    ├── .env
    ├── docker-compose.yml
    ├── docker-compose.server.yml
    └── update.sh
```

`docker-compose.server.yml` 用于让生产环境直接使用已导入镜像，避免服务器尝试根据源码构建：

```yaml
services:
  backend:
    image: labagent-backend:latest
  kb-worker:
    image: labagent-kb-worker:latest
  tool-runner:
    image: labagent-tool-runner:latest
  frontend:
    image: labagent-frontend:latest
```

## 3. 一次性准备

### 3.1 配置 SSH 免密

在 Mac 执行：

```bash
ssh-copy-id cs@172.29.7.233
ssh cs@172.29.7.233 'uname -m'
```

服务器应输出 `x86_64`。

### 3.2 初始化服务器目录

使用 `root` 在服务器执行一次：

```bash
mkdir -p /home/cs/labagent/labagent-offline
chown -R cs:cs /home/cs/labagent
chmod 700 /home/cs/labagent
```

上传 `.env` 后，建议限制其权限：

```bash
chmod 600 /home/cs/labagent/labagent-offline/.env
```

### 3.3 检查 Ollama

服务器执行：

```bash
curl http://127.0.0.1:11434/api/tags
ollama list
```

确认 `.env` 中 `OLLAMA_BASE_URL`、`OLLAMA_BASE_URLS` 与实际 Ollama 端口一致，并确认聊天模型和 Embedding 模型已经存在。离线服务器无法在部署时自动下载缺失模型。

## 4. Mac 部署脚本

创建 `~/labagent-deploy.sh`：

```bash
#!/bin/bash
set -euo pipefail

PROJECT_DIR="/Users/bytedance/learnAgent/LabAgent"
SERVER="cs@172.29.7.233"
REMOTE_DIR="/home/cs/labagent"
REMOTE_DEPLOY_DIR="${REMOTE_DIR}/labagent-offline"
TAR="/tmp/labagent-update.tar"
SSH_CONTROL_PATH="/tmp/labagent-ssh-$$"

cleanup() {
  ssh -S "$SSH_CONTROL_PATH" -O exit "$SERVER" >/dev/null 2>&1 || true
  rm -f "$SSH_CONTROL_PATH"
}
trap cleanup EXIT

# 默认更新后端和前端，也可传入 backend 或 frontend。
SERVICES=("$@")
if [ ${#SERVICES[@]} -eq 0 ]; then
  SERVICES=(backend frontend)
fi

for service in "${SERVICES[@]}"; do
  if [ "$service" != "backend" ] && [ "$service" != "frontend" ]; then
    echo "不支持的服务: $service，仅支持 backend、frontend"
    exit 1
  fi
done

cd "$PROJECT_DIR"

echo "==> 校验 Compose 配置"
docker compose config >/dev/null

echo "==> 构建 amd64 镜像: ${SERVICES[*]}"
for service in "${SERVICES[@]}"; do
  docker buildx build --platform linux/amd64 --load \
    -t "labagent-${service}:latest" "./${service}"
done

# kb-worker 和 tool-runner 与 backend 使用同一个镜像内容。
if [[ " ${SERVICES[*]} " == *" backend "* ]]; then
  docker tag labagent-backend:latest labagent-kb-worker:latest
  docker tag labagent-backend:latest labagent-tool-runner:latest
fi

echo "==> 检查镜像架构"
IMAGES=()
for service in "${SERVICES[@]}"; do
  IMAGES+=("labagent-${service}:latest")
  if [ "$service" = "backend" ]; then
    IMAGES+=("labagent-kb-worker:latest" "labagent-tool-runner:latest")
  fi
done

for image in "${IMAGES[@]}"; do
  architecture=$(docker image inspect "$image" --format '{{.Architecture}}/{{.Os}}')
  if [ "$architecture" != "amd64/linux" ]; then
    echo "镜像架构错误: $image $architecture"
    exit 1
  fi
done

echo "==> 打包镜像"
rm -f "$TAR"
docker save "${IMAGES[@]}" -o "$TAR"
ls -lh "$TAR"

echo "==> 建立 SSH 复用连接"
ssh -M -S "$SSH_CONTROL_PATH" -o ControlPersist=10m -fnNT "$SERVER"

echo "==> 上传镜像和配置"
scp -o ControlPath="$SSH_CONTROL_PATH" "$TAR" "${SERVER}:${REMOTE_DIR}/"
scp -o ControlPath="$SSH_CONTROL_PATH" docker-compose.yml .env "${SERVER}:${REMOTE_DEPLOY_DIR}/"

echo "==> 远端更新"
ssh -S "$SSH_CONTROL_PATH" "$SERVER" \
  "cd '${REMOTE_DEPLOY_DIR}' && bash update.sh ${SERVICES[*]}"

echo "==> 部署完成"
```

赋予执行权限：

```bash
chmod +x ~/labagent-deploy.sh
```

## 5. 服务器更新脚本

创建 `/home/cs/labagent/labagent-offline/update.sh`：

```bash
#!/bin/bash
set -euo pipefail

DEPLOY_DIR="/home/cs/labagent/labagent-offline"
UPDATE_TAR="/home/cs/labagent/labagent-update.tar"

cd "$DEPLOY_DIR"

if [ ! -f "$UPDATE_TAR" ]; then
  echo "未找到镜像包: $UPDATE_TAR"
  exit 1
fi

echo "==> 导入镜像"
docker load -i "$UPDATE_TAR"

SERVICES=("$@")
if [ ${#SERVICES[@]} -eq 0 ]; then
  SERVICES=(backend kb-worker tool-runner frontend)
fi

# 更新 backend 时同步重启使用相同代码的 Worker、Tool Runner，
# 并重启 frontend，避免 Nginx 保留重建前的 backend 容器地址。
if [[ " ${SERVICES[*]} " == *" backend "* ]]; then
  SERVICES+=("kb-worker" "tool-runner" "frontend")
fi

# 去重。
mapfile -t SERVICES < <(printf '%s\n' "${SERVICES[@]}" | awk '!seen[$0]++')

echo "==> 校验 Compose 配置"
docker compose \
  -f docker-compose.yml \
  -f docker-compose.server.yml \
  config >/dev/null

echo "==> 重启服务: ${SERVICES[*]}"
docker compose \
  -f docker-compose.yml \
  -f docker-compose.server.yml \
  up -d --no-build --no-deps --force-recreate "${SERVICES[@]}"

echo "==> 清理更新包和悬空镜像"
rm -f "$UPDATE_TAR"
docker image prune -f

echo "==> 当前服务状态"
docker compose \
  -f docker-compose.yml \
  -f docker-compose.server.yml \
  ps
```

使用 `root` 在服务器执行一次：

```bash
chmod +x /home/cs/labagent/labagent-offline/update.sh
chown cs:cs /home/cs/labagent/labagent-offline/update.sh
```

## 6. 日常更新

只更新后端，同时重启 `kb-worker`、`tool-runner` 和 `frontend`：

```bash
~/labagent-deploy.sh backend
```

只更新前端：

```bash
~/labagent-deploy.sh frontend
```

更新后端和前端：

```bash
~/labagent-deploy.sh
```

后端容器启动时会自动执行 Alembic 数据库迁移。更新期间容器会重建，正在进行的请求和任务可能中断，应避开使用高峰。

## 7. 首次部署基础镜像

日常脚本只上传业务镜像。首次安装或迁移服务器时，还需要在联网的 Mac 上准备 PostgreSQL、Redis 和 MinIO 镜像：

```bash
docker pull --platform linux/amd64 ankane/pgvector:latest
docker pull --platform linux/amd64 redis:7-alpine
docker pull --platform linux/amd64 minio/minio:latest

docker save \
  ankane/pgvector:latest \
  redis:7-alpine \
  minio/minio:latest \
  -o /tmp/labagent-base-images-amd64.tar

scp /tmp/labagent-base-images-amd64.tar \
  cs@172.29.7.233:/home/cs/labagent/
```

服务器导入：

```bash
docker load -i /home/cs/labagent/labagent-base-images-amd64.tar
rm -f /home/cs/labagent/labagent-base-images-amd64.tar
```

随后执行一次全量业务部署：

```bash
~/labagent-deploy.sh
```

查看服务状态：

```bash

  'cd /home/cs/labagent/labagent-offline && docker compose -f docker-compose.yml -f docker-compose.server.yml ps'
```

查看后端日志：

```bash
ssh cs@172.29.7.233 \
  'cd /home/cs/labagent/labagent-offline && docker compose -f docker-compose.yml -f docker-compose.server.yml logs --tail=200 backend'
```

查看 Worker 日志：

```bash
ssh cs@172.29.7.233 \
  'cd /home/cs/labagent/labagent-offline && docker compose -f docker-compose.yml -f docker-compose.server.yml logs --tail=200 kb-worker'
```

检查页面和后端：

```bash
curl -I http://172.29.7.233:8080
curl -I http://172.29.7.233:8989/docs
```

浏览器访问：

```text
http://172.29.7.233:8080
```

常见问题：

1. 出现 `exec format error`：镜像不是 `linux/amd64`，重新使用 `docker buildx build --platform linux/amd64` 构建。
2. 后端无法访问 Ollama：检查 `.env` 中 Ollama 地址、宿主机监听地址和防火墙。
3. 服务器尝试构建源码：确认命令同时指定了两个 Compose 文件，并包含 `--no-build`。
4. 上传失败：检查 `/home/cs/labagent` 所有者是否为 `cs`，以及磁盘剩余空间。
5. 后端启动失败：优先检查 Alembic、PostgreSQL、Redis、MinIO 和模型配置相关日志。
6. 更新后端后 API 返回 Nginx 错误页：重启 `frontend`，使 Nginx 重新解析 backend 容器地址。

## 9. 安全与数据

- 不在脚本和文档中保存 SSH 密码，使用 SSH 密钥登录。
- `.env` 含数据库、JWT、MinIO 和 Tool Runner 密钥，不提交 Git，不向无关用户开放。
- 日常更新不要执行 `docker compose down -v`，该命令会删除业务数据卷。
- `docker image prune -f` 只清理悬空镜像，不删除正在使用的镜像和数据卷。
- 数据卷包括 `pg_data`、`redis_data`、`minio_data`、`tool_workspaces` 和 `user_memories`，迁移服务器前必须单独备份。
