### rag_eval_007
- 问题：排查 NullPointerException 应该先看哪里？
- 标准答案：应先查看异常堆栈的第一行代码位置，再检查该行中每个对象是否可能为 null。
- 黄金证据：排查时建议先查看异常堆栈的第一行代码位置，再检查该行中每个对象是否可能为 `null`。
- baseline 答案：排查 `NullPointerException` 应优先检查以下位置：

1. **异常堆栈第一行代码**  
   查看异常发生的具体位置，定位到访问空对象的代码行。

2. **空对象的来源**  
   - 检查该行代码中每个对象是否可能为 `null`（如未初始化的对象、方法返回值、集合元素等）。
   - 若对象来自方法返回值，需验证该方法在异常输入下是否可能返回 `null`。

3. **常见场景**  
   - 未初始化的对象直接调用方法/属性。
   - 数组/集合中元素为 `null` 后被访问。
   - 字符串比较时用 `null` 对象调用 `equals`（如 `null.equals("abc")`）。

**示例**：若异常发生在 `obj.method()`，需确认 `obj` 是否为 `null`，或 `method()` 是否可能返回 `null`。
- current 答案：排查 `NullPointerException` 应优先检查以下位置：

1. **异常堆栈提示的首行代码**  
   异常信息会直接指向出错的代码行，优先检查该行中所有对象是否可能为 `null`，尤其是方法返回值、集合元素或未初始化的对象。

2. **方法返回值的空值校验**  
   若调用方未检查方法返回值是否为 `null`（例如 `String s = getStr(); s.length()`），需确认 `getStr()` 是否可能返回 `null`。

3. **字符串比较的 `equals` 调用**  
   避免直接使用 `null` 对象调用 `equals`，应先判断对象是否为 `null`，例如：  
   ```java
   if (s != null && s.equals("target"))
   ```

4. **集合/数组元素的空值**  
   检查从集合或数组中获取的元素是否为 `null`，例如遍历前未进行空值过滤。

**核心思路**：从异常定位代码 → 逐级检查对象是否可能为空 → 验证数据来源的可靠性。

### rag_eval_008
- 问题：二分查找可以用于无序数组吗？
- 标准答案：不可以。二分查找要求输入数组已经按升序排列，无序数组结果不可靠。
- 黄金证据：二分查找要求输入数组已经按升序排列。若数组无序，二分查找结果不可靠。
- baseline 答案：二分查找要求数组必须是有序的（升序或降序），否则无法正确工作。如果数组无序，需要先进行排序（如使用快速排序、归并排序等），然后再应用二分查找。直接在无序数组上使用二分查找会导致错误的结果。

二分查找 **不能** 直接用于无序数组。它要求数组必须是有序的（升序或降序），否则无法保证正确性。若数组无序，需先通过排序算法（如快速排序、归并排序）将其排序，再进行二分查找。

根据实验要求（实验三），您需要在有序数组上实现二分查找，并在实验报告中分析时间复杂度和边界条件。若直接在无序数组上使用，可能导致错误结果，影响实验成绩。请确保实验代码中对数组进行了排序处理。
- current 答案：二分查找**不能**直接用于无序数组。该算法依赖数组的有序性（如升序或降序）来确定中间元素与目标值的大小关系，从而每次将搜索范围缩小一半。若数组无序，无法保证中间元素的位置关系，导致算法无法正确缩小搜索区间，最终可能遗漏目标值或陷入无限循环。

如需在无序数组中查找元素，可考虑使用线性查找（时间复杂度 O(n)）或其他基于哈希的查找方法。

### rag_eval_010
- 问题：二分查找 mid 推荐怎么计算？
- 标准答案：推荐使用 `mid = left + (right - left) / 2`，可以避免整数溢出。
- 黄金证据：推荐使用 `left <= right` 作为循环条件，并用 `mid = left + (right - left) / 2` 避免整数溢出。
- baseline 答案：二分查找中 `mid` 的计算通常推荐使用以下两种方式：

1. **标准公式**：`mid = left + (right - left) // 2`  
   （避免整数溢出，尤其在C++/Java等语言中更安全）

2. **简化写法**：`mid = (left + right) // 2`  
   （Python等动态语言无需担心溢出，语法更简洁）

**推荐选择**：  
- 若使用 **Python**，两种方式均可，推荐简化写法。  
- 若使用 **C++/Java**，建议使用第一种公式以避免整数溢出风险。  

**注意**：无论哪种方式，需确保 `left` 和 `right` 的边界条件处理正确（如循环终止条件 `left <= right`）。
- current 答案：二分查找中 `mid` 的计算推荐使用以下两种方式：

1. **安全防溢出公式**  
   `mid = left + (right - left) // 2`  
   （适用于所有编程语言，避免 `left + right` 溢出）

2. **常见简写形式**  
   `mid = (left + right) // 2`  
   （在无整数溢出风险的语言如 Java/Python 中常用）

**核心区别**：  
两种方式最终效果相同，但第二种在极端大数场景下可能引发整数溢出（如 C++ 中 `left + right` 超过 int 范围）。推荐优先使用第一种公式以确保鲁棒性。
