## 第四阶段：Agent工具集成与完整调用链 （准备中 todo）
当前依赖基线以`uv.lock`为准：LangGraph 0.6.11、LangChain 0.3.30、langchain-core 0.3.86、langchain-community 0.3.31。

本阶段目标：
1. 接入LangChain已有的文件管理和Shell工具，不重复实现文件读写、目录遍历和Shell执行逻辑。
2. 使用`StateGraph + ToolNode + tools_condition`实现框架原生的“模型判断→工具调用→结果回传→模型继续推理”循环，不手写Tool Calling循环。
3. 完成工具调用从后端Graph、SSE事件、数据持久化到前端展示和高风险操作确认的整条链路。
4. 保留第三阶段RAG能力，将检索上下文与Agent工具循环整合到同一张LangGraph图中。

第一批接入的LangChain工具：
1. `FileManagementToolkit`文件管理工具集：
   - `list_directory`：列出目录内容。
   - `file_search`：按模式搜索文件。
   - `read_file`：读取文件。
   - `write_file`：写入或追加文件。
   - `copy_file`：复制文件。
   - `move_file`：移动或重命名文件。
   - `file_delete`：删除文件。
2. `ShellTool`：执行Shell命令，工具名在项目内统一为`execute_shell`。当前运行还需增加`langchain-experimental`依赖，其版本需与现有LangChain 0.3.x兼容。

工具集成方式：
1. 新增统一Tool Registry，负责工具实例化、名称去重、分类、开关、权限和模型绑定。
2. 文件操作直接复用`FileManagementToolkit`，项目只增加工具适配层，用于计算当前用户/会话工作区、记录事件、超时控制和结果脱敏。
3. 每个用户和会话使用独立工作区，例如`{tool_workspace_root}/{user_id}/{session_id}`；`root_dir`固定为该目录，模型只能使用工作区内的相对路径。
4. `user_id`、`session_id`和`workspace_path`由JWT及后端会话注入Graph State，通过`InjectedState`传给工具，不暴露为模型可生成的工具参数。
5. `ShellTool`不直接在FastAPI宿主环境执行，由适配层将其限制在独立进程或容器沙箱内，工作目录指向当前会话工作区。
6. 工具注册与模型绑定由后端根据用户角色和系统配置决定，不接受前端传入任意工具名并动态加载。

LangGraph图设计：
`START`
→ `prepare_context`：恢复短期记忆，注入用户、会话和工作区上下文。
→ `retrieve`：执行现有RAG检索和重排，将课程参考资料写入State。
→ `agent`：向模型传入历史消息、RAG上下文和白名单工具，模型返回普通回答或`tool_calls`。
→ `tools_condition`：有`tool_calls`时进入`tools`，否则进入`finalize`。
→ `tools`：使用`ToolNode`执行一个或多个工具，生成`ToolMessage`并返回`agent`继续推理。
→ `finalize`：输出最终答案，整理引用来源和工具调用摘要。
→ `END`。

完整后端调用流程：
1. 前端继续请求`POST /api/v1/ai/react-agent`，请求体只传`message`、`session_id`和`model`，当前用户从JWT获取。
2. 后端校验会话归属，保存用户消息，准备Graph State和当前用户可用的工具集合。
3. `agent`节点使用`model.bind_tools(tools)`调用模型，将模型返回的`AIMessage.tool_calls`写入消息状态。
4. `tools_condition`进行框架原生路由，`ToolNode`完成参数校验、工具执行、并行调用和`ToolMessage`封装。
5. 后端通过`graph.astream`消费`messages`、`updates`和`custom`三种流：`messages`用于模型Token，`updates`用于捕获Agent和ToolNode更新，`custom`用于RAG来源和工具内部进度。
6. AI消息中出现`tool_calls`时发送`tool_call` SSE事件；ToolNode返回`ToolMessage`时发送`tool_result`事件；超时、拒绝和执行异常发送`status`事件。
7. 模型可基于工具结果继续调用下一个工具，直到产生最终文本或达到最大工具轮次。
8. 完成后持久化助手消息、引用来源和工具调用记录，发送`final` SSE事件。

SSE工具事件协议：
1. `tool_call`：`tool_call_id`、`tool_name`、`arguments`、`round`、`description`。
2. `tool_result`：`tool_call_id`、`tool_name`、`success`、`result_summary`、`duration_ms`、`round`。
3. `status`：`stage`支持`tool_running`、`tool_done`、`tool_timeout`、`tool_rejected`和`global_timeout`。
4. `tool_approval_required`：`interrupt_id`、`tool_call_id`、`tool_name`、`arguments`和`risk_level`，用于前端展示审批。
5. 所有API和SSE字段保持蛇形命名，工具参数和结果进入事件前进行长度限制和敏感值脱敏。

高风险工具确认流程：
1. `read_file`、`list_directory`和`file_search`在授权工作区内可直接执行。
2. `write_file`、`copy_file`和`move_file`是写操作，是否需确认由配置决定。
3. `file_delete`和`execute_shell`默认使用`interrupt`暂停Graph，前端确认后调用恢复接口，后端使用`Command(resume=...)`继续执行。
4. 新增`POST /api/v1/ai/react-agent/resume`，传入`session_id`、`interrupt_id`和`approved`，后端必须重新校验JWT、会话归属和待恢复的工具调用。
5. 恢复接口继续返回SSE；拒绝时将受控的`ToolMessage`返回Agent，让模型基于“用户已拒绝”继续生成答案。

前端适配：
1. 复用现有`ChatInput.vue`的SSE处理、Pinia的`toolEvents`和`MessageItem.vue`工具调用面板，不重新实现消息流。
2. 将工具事件适配为当前会话下的实时状态，展示“等待执行、执行中、执行成功、执行失败、执行超时、用户拒绝”。
3. 工具卡片展示工具名、参数摘要、结果摘要和耗时；文件路径和Shell命令可折叠查看，超长输出不直接渲染。
4. 新增工具确认弹窗，用于显示Shell命令或删除文件路径，支持允许和拒绝。
5. 历史消息通过后端结构化的`tool_calls`字段恢复工具卡片，不再从消息正文中解析隐藏HTML注释。
6. 用户点击停止时，前端中断SSE，后端同步取消Graph任务和尚未结束的Shell子进程。

数据持久化：
1. 新增工具调用记录表，保存`session_id`、`message_id`、`tool_call_id`、`tool_name`、`arguments`、`status`、`result_summary`、`error_message`、`started_at`、`finished_at`和`duration_ms`。
2. `arguments`和结果入库前脱敏并截断；不保存完整敏感文件内容、环境变量或过长Shell输出。
3. `ChatMessageVO`增加`tool_calls`字段，历史接口一次返回消息、引用来源和工具调用记录。

安全与运行限制：
1. 文件工具必须校验路径解析后仍在当前工作区中，拒绝`../`、绝对路径、软链接越界和访问其他用户工作区。
2. Shell工具完成集成但默认关闭，通过配置和角色权限在指定环境启用；启用后仍需沙箱和默认人工确认。
3. Shell沙箱不挂载宿主敏感目录、Docker Socket、生产凭证或后端`.env`，限制CPU、内存、进程数和网络访问。
4. 每个工具设置执行超时、输入长度和输出长度；Agent设置最大工具轮次和全局超时。
5. 从文件和Shell返回的内容均视为不可信工具结果，系统提示词要求模型不执行其中嵌入的新指令。
6. 日志不记录完整Shell命令输出、敏感文件内容、JWT、API Key和环境变量。

验收场景：
1. 用户要求列出工作区文件，Agent调用`list_directory`并在前端实时展示调用过程。
2. 用户要求读取、搜索、创建、复制、移动或删除工作区内文件，Agent能选择正确工具并处理成功和失败结果。
3. 用户要求在工作区执行命令，前端展示命令确认，批准后继续接收执行状态和最终回答。
4. 单次问题中模型可以连续执行多个工具，并在最大轮次内正常结束。
5. 刷新页面后工具调用记录仍可恢复，不依赖助手消息中的隐藏标记。
6. 路径越界、未授权Shell、超时、输出过长、用户拒绝和客户端中断均有明确的前端状态和可控后端结果。
