# 前端代码质量沉淀

## 背景

本次仅针对 `frontend/src` 当前代码做静态阅读与规范沉淀，不直接改业务代码。重点关注：

- 是否存在冗余实现。
- 是否存在不规范或历史迁移残留。
- 是否有可复用的公共能力。
- 是否有可简化但不影响功能的改造点。

## 改造边界

本文档中的建议都应按“行为保持型优化”理解，不能影响现有功能：

- 不改变现有接口路径、请求参数、响应字段、SSE 事件字段和鉴权方式。
- 不改变现有页面入口、按钮行为、会话状态流转、工具事件展示和文件预览交互。
- 不改变现有视觉样式、默认模型、默认配置和用户可见文案，除非用户明确要求。
- 抽取公共工具时必须先覆盖原有调用场景，再替换重复实现，避免漏掉边界逻辑。
- 安全修复如果会影响 Markdown 展示效果，需要先确认受影响范围，优先采用白名单或等价渲染方式保持体验。
- 每次质量优化只处理一个明确问题，避免把无关格式化、样式调整或功能变更混入同一次改动。

## 总体结论

当前前端代码整体功能边界比较清晰，聊天主流程、工具事件展示、知识库和 Skills 页面已经能按模块拆分。但仍有一些从参考项目迁移或快速迭代留下的问题，建议按“安全优先、公共能力其次、历史清理最后”的顺序处理。

优先级最高的是 Markdown 与 `v-html` 的渲染安全：用户输入、模型输出、工具返回、Markdown 文件内容都应视为不可信内容，不能直接允许 HTML 注入。

## 高优先级问题

### Markdown 与 v-html 安全

涉及文件：

- `frontend/src/utils/markdown.js`
- `frontend/src/components/MessageItem.vue`
- `frontend/src/components/ToolActivityPanel.vue`
- `frontend/src/components/WorkspacePreviewPanel.vue`
- `frontend/src/views/SkillsManagement.vue`

现状：

- `markdown-it` 配置了 `html: true`，会保留 Markdown 中的原始 HTML。
- `MessageItem.vue`、`ToolActivityPanel.vue`、`WorkspacePreviewPanel.vue`、`SkillsManagement.vue` 都使用 `v-html` 渲染内容。
- `MessageItem.vue` 中用户消息只处理换行和双空格，没有转义 `<`、`>`、`&`、`"`、`'`。

风险：

- 用户输入、模型输出、工具返回、文件内容或 Skill 文档如果包含恶意 HTML/脚本，可能触发 XSS。
- 工具读取的工作区文件内容也不能默认可信，尤其是 Markdown 文件预览。

建议：

- 默认关闭 Markdown 原始 HTML，即 `markdown-it` 使用 `html: false`。
- 如确实需要支持少量 HTML，必须接入统一白名单净化函数，例如 `sanitizeHtml()`。
- 用户消息优先用文本节点渲染并配合 CSS `white-space: pre-wrap`，避免为了换行使用 `v-html`。
- 所有 `v-html` 使用点必须能说明输入来源和净化方式，不允许直接渲染后端、模型、用户或文件原文。

### localStorage 解析缺少容错

涉及文件：

- `frontend/src/stores/user.js`

现状：

- 初始化时直接执行 `JSON.parse(localStorage.getItem('userInfo'))`。

风险：

- 如果本地存储被手动修改、历史版本写入非法 JSON，应用初始化会直接抛错，导致页面不可用。

建议：

- 抽取 `safeJsonParse()` 或 `readJsonStorage()`。
- 解析失败时清理对应 key，并返回默认值。

### API 基础路径不统一

涉及文件：

- `frontend/src/api/index.js`
- `frontend/src/api/chat.js`

现状：

- axios 统一使用 `baseURL: '/api'`。
- SSE fetch 请求写死 `/api/v1/...`。
- `getBaseURL()` 的开发和生产分支都返回 `/api`，当前分支判断没有实际意义。

风险：

- 如果后续通过环境变量、代理或部署路径调整 API 前缀，普通 API 和 SSE 可能行为不一致。

建议：

- 抽取统一 `API_BASE_URL` 和 `buildApiUrl(path)`。
- axios 和 fetch 都复用同一个 API 基础路径。
- 如果不支持环境变量，则删除无意义的 dev/prod 分支；如果支持，则统一读取 `import.meta.env.VITE_API_BASE_URL`。

## 可复用沉淀

### HTML 转义工具

涉及文件：

- `frontend/src/utils/markdown.js`
- `frontend/src/components/WorkspacePreviewPanel.vue`
- `frontend/src/views/SkillsManagement.vue`

现状：

- 多处重复实现 `escapeHtml`。

建议：

- 新增 `frontend/src/utils/html.js`，统一提供 `escapeHtml()` 和未来可能的 `sanitizeHtml()`。
- Markdown 代码块、普通代码预览、用户消息文本渲染都复用同一实现。

### 点击外部关闭指令

涉及文件：

- `frontend/src/components/ChatInput.vue`
- `frontend/src/components/UserProfile.vue`

现状：

- 两个组件内都定义了 `vClickOutside`。

建议：

- 抽取为 `frontend/src/directives/clickOutside.js`。
- 在 `main.js` 全局注册或在组件中按需引入。
- 指令内部统一处理事件监听和卸载，避免重复代码。

### 模型配置

涉及文件：

- `frontend/src/components/ChatInput.vue`
- `frontend/src/stores/chat.js`

现状：

- 可选模型列表在 `ChatInput.vue`。
- 默认模型在 `stores/chat.js`。

风险：

- 新增、删除或修改模型时可能只改了其中一处，导致默认值和显示列表不一致。

建议：

- 新增 `frontend/src/constants/models.js`。
- 统一导出 `AVAILABLE_MODELS` 和 `DEFAULT_MODEL`。
- Store 只保存选中值，组件只负责展示。

### 下载与延迟工具

涉及文件：

- `frontend/src/views/KnowledgeManagement.vue`

现状：

- 多文件下载中重复出现 `await new Promise((resolve) => setTimeout(resolve, 200))`。
- Blob 下载 DOM 创建逻辑也可以独立复用。

建议：

- 新增 `frontend/src/utils/async.js` 提供 `sleep(ms)`。
- 新增 `frontend/src/utils/download.js` 提供 `downloadBlob(blob, filename)`。

## 可简化点

### Authorization 状态源重复

涉及文件：

- `frontend/src/api/index.js`
- `frontend/src/stores/user.js`

现状：

- 请求拦截器每次从 `localStorage` 注入 Authorization。
- 登录成功后又设置 `apiClient.defaults.headers.common.Authorization`。

建议：

- 保留请求拦截器作为唯一注入点。
- 登录和登出只维护 `localStorage` 与 Pinia 状态。

### 输入框高度同步入口重复

涉及文件：

- `frontend/src/components/ChatInput.vue`

现状：

- `@input` 调用 `handleInput()`。
- `watch(inputText)` 也会触发高度同步。
- 当前虽然用 `requestAnimationFrame` 合并，但逻辑入口仍偏多。

建议：

- 保留一个入口即可。
- 如果依赖 Vue 状态变化，优先保留 `watch(inputText)` 并在 DOM 更新后同步。
- 如果只处理用户输入事件，则保留 `@input`，避免 watch 再次触发。

### 文件选择清理分支重复

涉及文件：

- `frontend/src/views/KnowledgeManagement.vue`

现状：

- 上传成功、业务失败、异常分支都清空 `fileInput.value.value`。

建议：

- 放到 `finally` 中统一清理。
- 只在 `files.length === 0` 的早返回路径不处理即可。

## 不规范和迁移残留

### Java/Spring Boot 历史注释

涉及文件：

- `frontend/src/api/knowledge.js`

现状：

- 注释仍写着 “Spring Boot 接受 List 参数”。

建议：

- 改成当前 FastAPI/LabAgent 语义，例如“后端接口按重复 query 参数接收 ids”。

### userId 旧注释残留

涉及文件：

- `frontend/src/api/chat.js`

现状：

- JSDoc 仍描述 `userId` 参数，但接口已经不传用户 ID。

建议：

- 删除旧的 `userId` 注释。
- API 注释统一强调当前用户由 JWT 识别。

### 页面初始化职责偏重

涉及文件：

- `frontend/src/views/KnowledgeManagement.vue`
- `frontend/src/views/SkillsManagement.vue`
- `frontend/src/views/Chat.vue`

现状：

- 知识库和 Skills 页面挂载时也调用 `chatStore.initialize()`。

风险：

- 非聊天页面也会加载会话列表，页面职责不够聚焦。
- 如果后续会话列表加载变重，会影响管理页首屏体验。

建议：

- 确认调用目的是否只是为了 Sidebar 展示。
- 如果是 Sidebar 需要会话列表，可考虑由 Sidebar 自身或更轻量的导航 store 管理。

### Store 字段命名边界不够清晰

涉及文件：

- `frontend/src/stores/chat.js`

现状：

- 后端返回 `created_at`、`updated_at` 后，Store 内转换为 `createdAt`、`updatedAt`。

判断：

- 如果这些字段只在前端内部展示，属于本地 UI 状态，可以接受。
- 如果后续还会继续传回后端或作为 API 契约字段复用，应保持蛇形字段名。

建议：

- Store 中跨 API 边界的数据优先保留蛇形。
- 只有纯 UI 展示字段才允许驼峰，并在边界处显式映射。

## 后续建议顺序

1. 先修复 Markdown、`v-html` 和用户消息转义问题。
2. 再抽取 `html`、`clickOutside`、`models`、`async`、`download` 等公共工具。
3. 然后统一 API base URL 与 Authorization 注入方式。
4. 最后清理历史注释、死代码和非聊天页面的会话初始化职责。

## 可沉淀到 AGENTS.md 的规则

- 前端渲染不可信内容时，默认禁止 `v-html`；必须使用时先经过统一净化或转义。
- Markdown 默认不允许原始 HTML。
- 前端 API 契约字段继续遵守蛇形命名，跨后端边界不做隐式驼峰转换。
- axios 请求和 fetch/SSE 请求必须共用统一 API 基础路径。
- 可复用的小工具应放入 `utils`、`directives`、`constants` 或 `composables`，避免在多个组件内重复定义。
- 迁移参考项目代码时必须清理 Java/Spring Boot 历史注释，文档与注释以当前 FastAPI/Vue/LabAgent 为准。
