# LabAgent 文档

这里集中维护项目的功能说明、代码实现参考和未来优化计划。文档以当前仓库代码与配置为准；尚未实现的内容只放在“未来优化”中，不与现状混写。

## 功能介绍

- [产品与架构](功能介绍/产品与架构.md)：项目定位、用户角色、系统边界和总体架构。
- [核心功能](功能介绍/核心功能.md)：从用户视角介绍知识库、Agent、Tools、Skills、Memory、流式交互等能力。

## 技术实现

- [后端基础与数据](技术实现/后端基础与数据.md)：FastAPI 分层、认证权限、数据模型、存储和 API 约定。
- [RAG 与评测](技术实现/RAG与评测.md)：文档入库、三级检索、引用生成、增量索引和 RAGAS 评测。
- [Agent、工具与流式交互](技术实现/Agent工具与流式交互.md)：LangGraph 工具循环、审批、安全策略、SSE 与前端活动展示。
- [Skills](技术实现/Skills.md)：Markdown Skills 规范、渐进披露、运行时激活和资源安全。
- [Memory](技术实现/Memory.md)：短期上下文压缩、长期记忆目录、提取与检索。
- [前端实现与安全](技术实现/前端实现与安全.md)：Vue 前端结构、状态流、Markdown 安全和公共能力。
- [部署与模型接入](技术实现/部署与模型接入.md)：Docker Compose、Ollama、OpenAI 兼容接口和负载均衡。

## 未来优化

- [优化路线](未来优化/优化路线.md)：只记录与 LabAgent 后续升级直接相关、尚未落地的事项。

## 评测资料

`rag_eval/` 保存评测脚本所需的样例、数据准备脚本和历史输出。该目录结构被 `backend/app/eval/rag_eval.py` 使用，不作为普通说明文档拆分。

## 维护约定

1. 新增说明文档必须放在 `docs/` 的对应分类中。
2. README、AGENTS.md 和 Skill 自带的 `SKILL.md`/`references/` 属于工具或仓库入口文件，保留在其约定位置。
3. 实现变化时优先更新现有主题文档，不再按开发阶段新增“调研一、调研二”式文档。
4. 设计方案必须标注实现状态；未落地方案统一链接到未来优化路线。
5. 示例中的字段名与当前 Python/API 契约一致，统一使用蛇形命名。
