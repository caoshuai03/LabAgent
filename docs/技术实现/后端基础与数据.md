# 后端基础与数据

## 1. 技术基线

实际依赖以 `backend/pyproject.toml` 为准，当前核心组件为 Python 3.12、FastAPI、SQLAlchemy 2、Alembic、LangGraph、PostgreSQL、pgvector、Redis/ARQ 和 MinIO。

后端入口是 `backend/app/main.py`。应用生命周期负责扫描 Skills、初始化 LangGraph PostgreSQL checkpointer，并在退出时关闭 Memory 后台任务和连接池。

## 2. 分层结构

```text
backend/app/
├── api/v1/          # 路由、请求解析、响应包装
├── core/            # 配置、认证依赖、错误与统一响应
├── db/              # SQLAlchemy session 与模型基类
├── models/          # ORM 模型
├── repositories/    # 数据访问
├── schemas/         # Pydantic 请求/VO
├── services/        # 业务编排与外部资源封装
├── graph/           # LangGraph 状态图和 checkpointer
├── tools/           # LangChain 工具、注册表与安全策略
├── eval/            # RAG 评测
└── workers/         # ARQ 后台任务
```

路由只负责身份依赖、参数模型和响应转换。复杂业务进入 Service，数据库访问进入 Repository；同步的第三方组件在异步函数中通过 `asyncio.to_thread` 隔离。

## 3. API 契约

普通接口统一返回：

```json
{
  "code": 0,
  "data": {},
  "message": "ok"
}
```

- 返回类型写为 `BaseResponse[具体类型]`。
- 分页数据使用 `PageResult[T]`，结构为 `total` 和 `records`。
- 请求、响应、Query/Form 和 SSE JSON 字段统一使用蛇形命名。
- SSE 对话和文件下载使用 `StreamingResponse`，不套 `BaseResponse`。
- 当前 API 前缀由 `API_VERSION` 配置，默认 `/api/v1`。

主要路由：

| 前缀 | 能力 |
|---|---|
| `/user` | 注册、登录、密码、用户和状态管理 |
| `/ai` | Agent SSE、恢复、取消、压缩、工具、工作区文件、会话 |
| `/knowledge` | 文件上传任务、更新、分页、删除、下载 |
| `/skills` | 列表、详情、管理员刷新 |
| `/memory` | 用户 AGENTS.md 与长期记忆管理 |
| `/feedback` | 回答反馈 |

路由的精确路径以 `backend/app/api/v1/` 为准，新增接口时同步更新本表。

## 4. 认证、权限与安全

- `CurrentUser` 从 JWT 解析身份，业务接口禁止相信请求体中的用户 ID。
- `AdminUser` 用于管理员路由，例如添加用户、更新用户状态和刷新 Skills。
- 会话、工作区、消息、Memory 和知识库数据均按当前用户校验归属。
- 密码使用 Argon2，JWT 密钥从环境变量读取。
- 异常由统一处理器转换为业务错误响应，日志不记录密码、JWT 或 API Key。

## 5. 主要数据

| 数据 | 存储 | 说明 |
|---|---|---|
| 用户 | `user` | 账号、密码哈希、角色和状态 |
| 会话 | `chat_session` | 用户归属、标题和逻辑删除 |
| 消息 | `chat_message` | 用户/助手消息、引用和展示数据 |
| 工具调用 | `chat_tool_call` | 调用参数摘要、状态、结果和耗时 |
| 知识文件 | `kb_file` | 原文件元数据、状态和 MinIO 地址 |
| 上传任务 | `kb_upload_task` | ARQ 任务阶段、尝试次数和错误 |
| 反馈 | `user_feedback` | 用户反馈 |
| Agent 状态 | LangGraph checkpoint 表 | 消息状态、中断、Skills 与摘要 |
| 文档切片 | pgvector 表 | 文本、metadata 和 embedding |
| 切片索引记录 | SQLRecordManager 表 | 增量索引和来源清理 |
| 长期记忆 | 用户目录内 Markdown | AGENTS、事实、偏好和经验 |

数据库表结构由 `backend/alembic/` 迁移维护。ORM、Pydantic 和 API 字段保持同名蛇形。

## 6. 存储与异步任务

知识文件原件写入 MinIO，业务记录写入 PostgreSQL。上传接口先完成安全校验和原件存储，再创建任务并投递 Redis/ARQ；Worker 执行解析、切分、向量化和索引。失败时记录可见阶段与原因，并提供重试入口。

文件上传校验包含：

- 文件非空和大小上限。
- 扩展名白名单。
- Content-Type 与扩展名匹配。
- 文件名路径字符和响应头控制字符净化。

## 7. 配置原则

所有地址、密钥、模型名和阈值通过 `Settings` 从环境变量读取。新增配置时同时更新：

1. `backend/app/core/config.py`
2. `.env.example`
3. `docker-compose.yml`（容器运行需要时）
4. [部署与模型接入](部署与模型接入.md)

禁止在业务代码中写死密钥、Token、密码和服务地址。
