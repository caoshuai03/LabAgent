# 前端实现与安全

## 1. 技术与结构

前端使用 Vue 3、Pinia、Vue Router、Axios、markdown-it 和 highlight.js，构建工具版本以 `frontend/package.json` 为准。

```text
frontend/src/
├── api/           # 普通 API 与 SSE
├── components/    # 对话、活动、审批、预览等组件
├── composables/   # Toast 等组合逻辑
├── constants/     # 模型等常量
├── directives/    # 点击外部、提示等指令
├── stores/        # 用户、会话、上传和主题状态
├── utils/         # HTML、Markdown、存储和异步工具
└── views/         # 登录、对话、知识库、Skills、Memory
```

## 2. API 与状态流

`api/index.js` 定义统一 `API_BASE_URL`、Axios 实例、Authorization 拦截器和登录失效处理。其他普通 API 复用该客户端。

SSE 因需要读取 `ReadableStream` 使用 `fetch`，但 URL 仍通过统一基础路径构造，Token 只在存在时加入请求头。解析器按空行分隔 SSE 事件并兼容流分片。

后端契约保持蛇形命名；组件内部纯 UI 状态可使用驼峰。边界映射示例：

```text
SSE event_type -> 前端内部 eventType
tool_call_id   -> 活动项 id
```

Pinia chat store 按会话维护消息、运行状态、工具事件、审批、reasoning 和工作区预览标签，切换会话时不能复用另一会话的临时运行状态。

## 3. 核心组件

| 组件 | 职责 |
|---|---|
| `ChatInput.vue` | 发起/恢复/取消 SSE，请求事件分发 |
| `MessageItem.vue` | 消息、Markdown、引用和产物链接 |
| `ToolActivityPanel.vue` | 工具调用聚合与状态展示 |
| `ToolApprovalInline.vue` | 高风险工具批准或拒绝 |
| `ReasoningPanel.vue` | 可展示 reasoning 片段 |
| `WorkspacePreviewPanel.vue` | 工作区文本/Markdown/代码预览与下载 |
| `KnowledgeManagement.vue` | 文件与异步上传任务 |
| `SkillsManagement.vue` | Skills 列表与详情 |
| `MemoryManagement.vue` | AGENTS 和长期记忆管理 |

## 4. 不可信内容边界

以下内容均应视为不可信：

- 用户输入。
- 模型回答和 reasoning。
- RAG 文档与引用摘要。
- 工具输出和工作区文件。
- Skill 正文与参考资源。

`v-html` 只能接收经过统一安全处理的结果。代码块高亮内容必须转义；动态属性、产物路径和链接协议也必须校验。

### 当前已知缺口

`frontend/src/utils/markdown.js` 当前配置了 `html: true`，并把渲染结果交给多个 `v-html` 入口。这意味着 Markdown 原始 HTML 尚未按项目安全要求关闭或净化。该问题属于需要优先修复的现存风险，不能在文档中描述为“已完成安全处理”；具体任务列入[优化路线](../未来优化/优化路线.md)。

`ToastContainer.vue` 的图标 `v-html` 来源是内部常量，仍应保持该数据源封闭，不能改为显示外部字符串。

## 5. 已沉淀公共能力

- `utils/html.js`：HTML 转义。
- `utils/markdown.js`：Markdown 与代码块渲染、产物尾块处理。
- `utils/storage.js`：localStorage JSON 容错。
- `utils/async.js`：延迟等通用异步逻辑。
- `directives/clickOutside.js`：点击外部关闭。
- `constants/models.js`：模型配置。
- `api/index.js`：API 基础路径、认证注入与失效处理。

新增重复逻辑前先检查这些模块，避免在组件内维护多套实现。

## 6. 变更检查清单

1. API 字段是否与后端蛇形契约一致。
2. 普通 Axios 和 SSE 是否共用 API 基础路径与认证失效行为。
3. 用户/模型/工具内容是否经过转义、净化或安全的文本绑定。
4. 会话切换、取消、审批恢复和历史恢复是否保持状态隔离。
5. 新活动事件是否同时支持实时流与历史消息。
6. 文件预览是否限制路径、类型、大小和链接协议。
7. 只改前端时运行测试与构建，并仅重建前端 Docker 服务。

验证命令：

```bash
cd frontend
npm run test
npm run build
```
