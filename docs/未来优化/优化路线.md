# 优化路线

本页只记录当前代码尚未完成、且对 LabAgent 后续升级有直接价值的事项。内容按优先级组织，不代表已经落地；完成后应迁入对应技术文档并从本页删除。

## P0：安全与正确性

### Markdown 原始 HTML

现状：`frontend/src/utils/markdown.js` 使用 `markdown-it({ html: true })`，多个组件通过 `v-html` 展示模型、Skill 或文件渲染结果。

目标：

- 默认设置 `html: false`。
- 如确需支持少量 HTML，引入统一白名单净化并覆盖所有 `v-html` 入口。
- 校验链接协议，禁止 `javascript:` 等危险 URL。
- 增加 XSS 用例：事件属性、`script`、SVG、危险链接、代码块和嵌套 Markdown。

### Prompt Injection 纵深防御

- 给 RAG 文档、Skill 资源、Memory 和工具结果加明确的不可信边界标记。
- 检索内容不得改变身份、权限、审批和 ToolPolicy。
- 对外部文档中的工具诱导、密钥索取和数据外传建立回归集。
- 日志与 SSE 继续使用集中脱敏，避免新增事件绕过处理。

### Memory 隐私

- 增加敏感信息拒绝保存与用户可审计的提取原因。
- 支持按来源会话撤销自动记忆。
- 明确保留期、批量导出和清空能力。

## P1：检索与回答质量

### 领域评测集

- 建立课程知识、实验平台操作、代码排错和报告规范四类真实样例。
- 每条样例记录标准答案、应命中文档、难度和失败类型。
- CI 执行小规模无外部依赖检查；完整 RAGAS 在专用环境运行。

### 上下文组织

当前检索结果主要按 rerank 顺序交给模型。可评估：

- 使用 LangChain 文档组合链统一格式、长度预算和来源标记。
- 对长上下文进行首尾重排，缓解 “lost in the middle”。
- 按问题动态分配 RAG、Memory、Skills 和历史摘要预算。

实施前必须用固定评测集验证，不能只因调研结论直接改生产链路。

### 检索增强

- 评估中文分词器替换当前单字 BM25 的收益与成本。
- 增加 metadata 过滤、课程/章节权限过滤和多知识库选择。
- 根据问题复杂度动态决定 MultiQuery 数量和 rerank top_n。
- 对 query rewrite、BM25 和 rerank 建立独立缓存与可观测指标。

## P1：Agent 稳定性与可观测性

- 将重复调用、轮数耗尽、工具超时和用户取消纳入统一运行指标。
- 记录每轮模型耗时、工具耗时、token、检索候选数和降级原因。
- 为 checkpoint 中断恢复增加故障注入测试。
- 评估并行只读工具；审批和有副作用工具仍需顺序、幂等和冲突控制。
- Agent 输出与工具产物建立稳定关联，减少依赖模型在正文中重复输出路径。

## P2：Skills 生命周期

- 支持课程、租户或教师作用域，不同用户只看到有权限的 Skills。
- 增加版本、发布、回滚、签名或内容哈希。
- 提供受控在线编辑和校验预览；发布仍需管理员审批。
- 建立 Skill 触发准确率、任务完成率和资源读取成本评测。

在这些能力完成前，保持应用内置目录只读加载，不把 Skill 当作任意脚本执行入口。

## P2：Memory 质量

- 长期记忆数量增长后，引入 metadata/向量混合检索，保留当前 Markdown 作为可读事实源。
- 为冲突事实提供时间、置信度和替换关系。
- 根据记忆类型设置不同固定注入与检索策略。
- 评估上下文窗口和 tokenizer 配置化；改变 200K/80%/10% 前需覆盖不同模型。

## P2：部署扩展

- 将 Ollama 端点健康、模型库存和延迟纳入选择，替代纯轮询。
- 多后端副本共享端点健康状态，避免各进程独立判断。
- 为知识库 Worker 增加并发、重试、死信和任务清理指标。
- 生产环境补齐反向代理 TLS、密钥管理、备份恢复和最小网络暴露。

## 实施要求

每项优化落地时：

1. 先记录基线、风险和验收指标。
2. 优先复用 LangGraph/LangChain 已有能力，并查证当前版本官方 API。
3. 保持现有 API、交互和默认配置不变，除非需求明确允许变更。
4. 补齐类型检查、后端测试、前端测试/构建或 Compose 检查。
5. 更新对应技术文档，把本页条目移除或标记为后续子阶段。
